## 2026-11-10 接下來 7 天的行程清單
- 改了：`src/lib/google-calendar.ts` 新增 `listUpcomingEvents`（對每個可寫入日曆呼叫 `events.list`，`singleEvents=true` 展開重複事件，依開始時間合併排序）、`src/app/actions.ts` 新增 `listUpcomingEventsAction(timeMin, timeMax)`（檢查 ISO 格式、區間 ≤ 8 天）
- 改了：`src/components/upcoming-events.tsx`（新）、`src/components/quick-add-view.tsx`（新，從 `page.tsx` 搬出來變成 client component，持有 `refreshKey`）、`src/components/quick-add-form.tsx` 加 `onCreated`，新增成功後清單重抓
- 為什麼：使用者問「能不能在 QuickCal 上看到行事曆，還是一定要開 Google 日曆」；`calendar.events` 權限本來就能讀事件，不用改 OAuth scope、不用重新登入
- 決定：時間範圍由瀏覽器算（現在 → 本地第 7 天結束），伺服器只驗證不算日期，避免伺服器不知道使用者時區
- 決定：只顯示有行程的日子；進行中的事件歸在「今天」；全天事件排在該天最前；全天結束日 API 是 exclusive，顯示時減一天
- 決定：桌面版清單放在左欄標題下方（表單 `row-span-2` 佔右欄兩列），手機版放在表單與送出按鈕之後
- 決定：先不做月曆格子；360px 手機排不下，且 Google 日曆已經有
- 審查後修：Server Action 的 promise 補 `.catch`（離線時骨架畫面不會一直轉）；各日曆用 `Promise.allSettled`，單一日曆失敗只略過，授權錯誤才整批回報
- 已知限制：每個日曆最多抓 50 筆，沒有翻頁；排序用 `Date.parse`，全天事件的日期被當成 UTC 午夜，但 UI 把全天事件固定排在每天最前面所以看不出來
- 通知：QuickCal 建立的事件沒帶 `reminders`，會套用該日曆的預設提醒，由 Google 日曆 app／信件通知；QuickCal 自己推播要 Web Push（VAPID、service worker、訂閱資料庫、排程器），暫不做
- 待辦：登入後的畫面要由使用者實測（桌面、手機），確認清單位置與高度；之後更新 `docs/screenshots/quick-add-*.png`
